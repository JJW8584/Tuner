# 구조와 오디오 처리

```text
lib/
  main.dart                         # 의존성 조립과 앱 진입점
  app/                              # 앱 수명과 테마
  features/tuner/
    domain/                         # 피치 검출, 음명, 센트, LED 정책, 인터페이스
    data/                           # record / SharedPreferences 어댑터와 isolate
    presentation/                   # ChangeNotifier 컨트롤러, 화면, 재사용 위젯
test/
  features/tuner/{domain,data,presentation}/
  support/
```

별도 상태 관리 패키지 없이 Flutter의 `ChangeNotifier` / `ListenableBuilder`를 사용합니다. `TunerController`가 마이크 세션·화면 상태·기준 주파수 변경을 조정하고, 앱 진입점에서 구체적인 어댑터를 주입합니다.

## 신호 경로

1. `record`가 44,100 Hz, mono, little-endian PCM16 스트림을 엽니다. 자동 게인·에코 제거·잡음 억제를 요청하지 않으며 Android에서는 unprocessed 입력을 요청합니다. 기기별 실제 오디오 처리는 하드웨어에 따라 달라집니다.
2. PCM 바이트를 `TransferableTypedData`로 장기 실행 isolate에 전달합니다.
3. `PcmFrameBuffer`가 홀수 바이트 경계를 보존하고 4,096샘플 프레임을 2,048샘플 간격으로 생성합니다. 프레임 길이는 약 93ms, 갱신 간격은 약 46ms입니다. 이는 전체 기기 지연의 보장값이 아닙니다.
4. YIN 누적 평균 정규화 차분 함수로 기본 주파수를 찾습니다. 첫 유효 최소값이 완성되면 이후 지연 구간 계산을 생략하고 프레임 간 작업 배열을 재사용합니다. 2배 다운샘플링으로 후보를 찾고 원본 샘플에서 보간해 고음 정밀도를 보완합니다. RMS와 신뢰도로 무음·잡음을 제외합니다.
5. 세 프레임 중앙값과 로그 주파수 평활화로 일시적인 배음 오인식을 줄입니다. 기본 500ms 이상 신뢰할 음이 없으면 표시를 지웁니다. 작은 소리 기준과 신뢰도·유지 시간은 `audio_sensitivity.dart`에서 함께 관리합니다.
6. `69 + 12 × log₂(f / A4)`에서 가장 가까운 MIDI 음과 센트 편차를 계산합니다. 음명은 C, C#, D, D#, E, F, F#, G, G#, A, A#, B만 사용합니다.

## 표시 정책

- 정확한 음: ±3센트 기준의 초록 중앙 화살표. 경계 깜빡임을 줄이는 0.5센트 히스테리시스가 있습니다.
- 높은 음: 위쪽 LED를 중앙에서 바깥으로 누적 점등합니다.
- 낮은 음: 아래쪽 LED를 같은 방식으로 점등합니다.
- 중앙부터 초록 / 노랑 / 주황 / 주홍 / 빨강, 각 5개씩 5줄입니다. 줄 경계는 약 3 / 10 / 20 / 30 / 40센트이며 0.75센트 히스테리시스를 적용합니다.
- A4 기준은 430~450 Hz, 1 Hz 단위이며 저장은 250ms 디바운스 후 순차 수행합니다.

## 화면과 시스템 안전 영역

`SafeArea` 안의 실제 가용 크기로 배치하며, OS가 제공하는 노치·카메라 cutout·상태 표시줄·하단 내비게이션 여백을 사용합니다. 하단 `viewPadding`도 유지합니다. LED와 음은 하나의 단위로 균일 배율을 적용하므로 원형과 세그먼트 비율이 유지됩니다.

세로 화면은 로고 → 음정 표시 → 하단 패널 순서입니다. 폭이 충분한 가로 화면은 로고 아래에서 음정 표시와 패널을 좌우로 배치합니다. 태블릿에서는 최대 콘텐츠 폭을 제한합니다. 아주 짧은 분할 화면이나 큰 오류 문구·글자 확대는 안전 영역 내부 스크롤로 처리하고, 정상 휴대폰 크기에서는 스크롤 없이 표시합니다.

## 수명과 개인정보

첫 화면이 표시되면 마이크를 자동으로 시작하고 필요한 경우 권한을 요청합니다. 권한 대화상자의 일시적인 inactive/resumed 전환에서는 중복 요청하지 않습니다. 앱이 hidden/paused/detached 상태가 되면 마이크를 종료하고, 실제 백그라운드 전환 후 resumed가 되면 다시 시작합니다. 빠른 종료·복귀도 순차 세션 큐로 처리합니다. 권한 거부나 입력 오류는 화면에 표시하며, 권한을 변경하거나 연결을 복구한 뒤 앱으로 돌아오면 다시 시도합니다. PCM은 메모리에서만 분석하며 파일·서버로 저장하지 않습니다.

현재는 단일 음 분석기입니다. 화음, 주변 음악, 큰 소음, 블루투스 입력은 검출 품질에 영향을 줄 수 있습니다. 지원 검출 범위는 약 40~2,000 Hz이며 저음 베이스의 E1도 포함합니다.
