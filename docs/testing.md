# 검증 기록

2026-10-31, Windows의 X: 개발 환경에서 확인했습니다.

## 자동 검증

- Dart formatter: 통과
- `flutter analyze --fatal-infos`: 문제 없음
- `flutter test`: 62개 통과
- `flutter build apk --debug`: 통과

테스트는 41.203~1,975.53 Hz의 선택된 합성 사인파에서 2센트 이내 검출, 강한 배음과 잡음, 무음·DC·백색 잡음 제외, 12음명과 옥타브, 기준음 보정, LED 방향·누적·히스테리시스를 확인합니다.

PCM의 홀수 바이트 경계·중첩 프레임, isolate 재시작, 권한 거부 후 재시도, 시작 중 중단, 중복 시작, 오디오 오류, 오래된 설정 읽기, 무음 복귀, 빠른 Hz 연속 입력도 포함합니다. 320×568 / 844×390 / 768×1024 화면과 2배 글자 확대에서 위젯 overflow가 없음을 확인했습니다.

## Android 에뮬레이터 확인

Pixel 7 구성 / Android 16 API 36 / x86_64에서 다음을 확인했습니다.

- APK 설치와 앱 실행
- 앱 실행 시 자동 마이크 시작과 PCM 입력 세션
- 자동 시작·권한 거부·권한 대화상자 복귀·빠른 백그라운드 복귀 위젯 검증
- 442 Hz 설정 후 프로세스 종료·재실행 시 값 복원
- Home으로 이동한 후 RECORD_AUDIO 사용 종료와 복귀 시 자동 재시작
- AndroidRuntime / Flutter 오류 로그 없음

화면 캡처: [대기 화면](images/android-idle.png).

추가 레이아웃 검증에서는 상단 59px 노치·하단 34px 홈 인디케이터, 하단 48px 시스템 버튼, 가로 화면 좌우 cutout, 긴 화면과 태블릿의 시스템 여백을 가정해 로고·LED·패널의 렌더링 경계를 확인했습니다. 일반 화면의 스크롤 범위는 0이며, 회전해도 기준 주파수 설정이 유지됩니다.

독립된 주파수 표 16개로 옥타브와 B→C 경계를 검증했습니다. 느린 설정 읽기가 첫 화면과 마이크 시작을 막지 않는지도 확인했습니다. [시작·피치 최적화 기록](startup-and-pitch.md)에 측정 조건과 결과를 정리했습니다.

작은 기타 입력에서는 이전 RMS 문턱 아래인 개방현 6개와 감쇠하는 E2 60프레임을 검증했습니다. 감도 조정 후에도 무음·DC·비주기 잡음을 제외하고, 화면 필터가 검출기의 새 신뢰도 기준을 수용하는지 확인했습니다. [감도 조절 방법](sensitivity.md).
